# SigLIP VLA-Style Navigation: Visual-Token Reduction vs Language-Grounded Task Success

A small, reproducible **perception → language grounding → planning → action** experiment. A pretrained SigLIP image-text model picks the goal object named in a natural-language instruction from rendered RGB observations of a 2D gridworld. A shortest-path planner then moves the agent there. The question is how **reducing visual tokens (196 → 144 → 100 → 49)** changes language grounding, navigation success and inference latency.

> **Scope.** This is a *modular, VLA-inspired* system: a frozen vision-language model for perception and grounding, plus an explicit planner. It is **not** an end-to-end learned Vision-Language-Action foundation model. Nothing is trained, actions are not produced by a neural network, and the environment is a synthetic 2D gridworld rather than a robot.

> **Status of results.** Every number in *Results* is generated by `kaggle_notebook.ipynb` on a Kaggle GPU and written into this README from `results/*.csv`. Until that run has happened the section is intentionally empty. No result here is estimated or entered by hand.

---

## Motivation

VLA policies condition actions on camera images and language. Their visual front end turns each frame into hundreds of tokens, and with several cameras, many frames and long histories, these tokens dominate the context and the control-loop latency. Reducing visual tokens is one of the main levers for efficient long-context VLA systems. But a robot fails differently from a classifier: a single wrong grounding decision sends the agent to the wrong object.

The companion project **efficient-vit-bench** measured, on a Kaggle Tesla T4, that the same deterministic token reduction in SigLIP-Base/16 gives:
- a 1.51× encoder speed-up at 100 tokens (batch 8), and 1.96× for end-to-end classification at batch 64;
- a zero-shot CIFAR-10 accuracy drop from 92.59% to 78.28% (−14.31 pp, paired 95% CI [−15.08, −13.56]).

This project asks the same question **in a closed control loop**: does the drop in grounding accuracy carry over into task failure, how do the failures look, and what does the agent gain in per-decision latency?

## Research questions

1. How do language-grounding accuracy and navigation success change as SigLIP receives 196, 144, 100 or 49 visual tokens per object crop?
2. Which kinds of grounding errors (colour vs shape) appear as tokens are removed?
3. What per-decision latency does token reduction buy, and how does that trade against task success?

## System

```
instruction ("Navigate to the red circle.")  ──►  SigLIP text tower (once per string, FP32, cached)
                                                                    │
RGB frame ─► pixel-only candidate proposals ─► crops ─► SigLIP vision tower with N tokens ─► logits
                                                                    │
                                     argmax over candidates  ◄──────┘   (goal = selected cell)
                                                │
                    BFS shortest path on the occupancy grid ─► one move ─► new frame (repeat)
                                                │
                    arrive on the selected object ─► STOP   (success = stopped on the true target)
```

**Environment (`src/gridworld.py`).**
- 10×10 grid, 15% wall cells, 5 objects drawn from 5 colours (red, green, blue, yellow, purple) × 3 shapes (circle, square, triangle). Instructions use 4 templates ("Navigate to / Go to / Move to / Find the {colour} {shape}.").
- Every scene contains a distractor with the target's colour (different shape) and one with its shape (different colour), so both words in the instruction matter. Colour–shape pairs are unique within a scene.
- Every object is reachable from the start and at least 3 steps away, so how close an object is to the start says nothing about which one is the target. The tests check that the text-agnostic "nearest" baseline sits at chance.
- Episode *i* is generated from `np.random.default_rng(42 + i)`. The episode set (default 300) is saved to `results/episodes.json`, and every policy runs on exactly these scenes, obstacles, starts and instructions.
- Rendering: 32 px per cell (320×320 RGB), anti-aliased shapes, grey floor and walls, and the agent drawn as a black "X".

**Perception (`src/perception.py`).**
- *Where* objects are is found from pixels only: floor, walls and agent are achromatic, objects are saturated, so cells with enough high-chroma pixels become candidates.
- The run reports how often these proposals equal the true object cells (they matched in 100% of the 300 test scenes during development).
- Each candidate becomes a 48×48 crop (the cell plus a quarter-cell margin), which the SigLIP image processor resizes to 224×224.

**Grounding (`src/siglip_scorer.py`, `src/model_wrapper.py`, `src/token_selection.py`).**
- *Which* candidate is the target is decided by SigLIP alone: the logit of each crop against the instruction, `cos(image, text) · exp(logit_scale) + logit_bias`, exactly as in `SiglipModel.forward`. The highest-scoring crop is the goal.
- Token reduction uses the same deterministic uniform k×k subsets of the 14×14 patch grid as efficient-vit-bench, applied after the pretrained embedding layer so each kept patch keeps its own position embedding.
- `token_selection.py` and `model_wrapper.py` are copied unchanged from that project.

**Planning and control (`src/agent.py`).**
- Breadth-first shortest path over walls and non-goal objects. Using the true occupancy grid for collision-free planning is a deliberate simplification.
- The agent re-perceives and re-plans at **every step** (closed loop, no memory), so a grounding decision that flips mid-episode changes the route.
- Arriving on the selected object counts as STOP. The step budget is 50.

**What uses ground truth.**
- Planning uses the true wall and object *occupancy* (no identities).
- Evaluation uses the true target to score success and classify failures.
- Only the `oracle (GT target)` policy uses the true target to choose its goal. It is a labelled sanity check that must reach 100% success at the optimal path length, otherwise the run stops.

## Policies compared

| Policy | Goal choice | Uses language | Purpose |
|---|---|---|---|
| SigLIP 196 / 144 / 100 / 49 tokens | argmax SigLIP logit vs own instruction, every step | yes | main comparison |
| SigLIP 196, shuffled instruction | same, but with another episode's instruction (never naming this target) | wrong text | control: success should collapse to about chance if the choice really depends on language |
| random candidate | uniform over proposals at step 0 (seeded), then committed | no | chance level (≈ 1/5) |
| nearest candidate | shortest path from start at step 0, then committed | no | text-agnostic heuristic |
| oracle (GT target) | true target cell | — | environment/planner sanity check |

## Validation (run before any reduced-token configuration)

1. **Oracle check**: 100% success and every path at optimal length, or the run stops.
2. **Proposal check**: share of first observations where pixel proposals equal the true object cells.
3. **SigLIP gate (FP32)**: on the step-0 crops of the first 8 episodes, the custom 196-token scoring must match `SiglipModel(input_ids, pixel_values).logits_per_image`.
   - It checks the full crop × instruction logit matrix and the per-crop logits the agent uses, with `atol=1e-4`, `rtol=1e-5` and 100% argmax agreement. Image and text embeddings are compared too.
   - On failure the script raises and no token configuration is evaluated (`results/validation.json`).
4. **Precision check**: the image tower then runs in FP16 (logits stay FP32), and FP16-vs-FP32 agreement on the chosen target is recorded.

## Metrics

- **Task success**: share of episodes in which the agent stops on the true target within 50 steps.
- **Target-selection accuracy (step 0)**: share of episodes whose first grounding decision picks the true target. Also reported: per-step selection accuracy and the number of goal switches.
- **Mean steps per successful episode** (with the optimal length for the same episodes), and **SPL** (success weighted by optimal/actual path length).
- **Failure categories**, from the object the agent stopped on: wrong shape (colour right), wrong colour (shape right), wrong colour and shape, timeout (no stop within 50 steps), no candidates. Episodes where the planner found no path are counted separately.
- **Uncertainty**: paired percentile bootstrap over episodes (10,000 resamples, seed 42) for each rate and for the difference vs SigLIP-196. The same resampled episode sets are used for every policy.
- **Latency**, each stage measured separately and never mixed:
  - `decision_gpu_single_agent`: one agent's ~5 preprocessed crops on the GPU → embed → select → encoder → head → logits → argmax.
  - `encoder_only_single_agent`: precomputed tokens → encoder → head (comparable to efficient-vit-bench Experiment A).
  - `decision_gpu_64_agents_batched`: 64 agents' crops scored in one batch.
  - `cpu_render_and_proposals`, `cpu_crop_and_preprocess`, `cpu_bfs_planning`: CPU stages that do not depend on the token count.
  - 10 warm-up iterations, 60 timed reps, CUDA synchronised before and after each rep, configurations interleaved.

## Limitations

- **Synthetic, simple visuals.** Flat coloured shapes on a grid are far easier than real scenes, and far from SigLIP's training images. Results say nothing direct about real robot cameras.
- **Perception is factorised.** Object locations come from a colour-saturation heuristic that works because the renderer guarantees it; only the *identity* choice is learned. A real system would need a detector or full-scene grounding.
- **Crops, not full frames.** Token reduction is applied to each 48×48 crop (upsampled to 224), not to a full camera frame. The 196-token budget is per candidate, so total visual tokens per decision ≈ 5 × N.
- **Ground-truth planning.** The planner uses the true occupancy grid, so all navigation errors are grounding errors by construction. There is no exploration, partial observability or motor noise.
- **Single prompt per episode, no prompt engineering.** The instruction string is scored directly. Better prompts or ensembles may change absolute numbers.
- **One model, one GPU, one precision**, as in efficient-vit-bench. Kaggle T4 clocks are logged but not locked.
- **Not a learned VLA.** No action head, no training, no long-horizon memory. Findings concern the perception/grounding component of a VLA pipeline.

## Future research directions

- Full-frame grounding (patch-level text similarity or a detection head) so that token reduction acts on the whole observation, as in a real VLA camera stream.
- Content-aware token reduction (attention-based pruning, token merging) and its effect on grounding errors at equal budgets.
- Partial observability, multi-step instructions ("go to the red circle, then the blue square") and multi-frame histories, where visual tokens accumulate in context.
- Replacing the planner with a learned policy head, and measuring how perception latency limits control frequency.
- Real or photo-realistic scenes (e.g. household simulators) to test whether the trade-off holds beyond synthetic shapes.

## Reproducing on Kaggle

1. Create a Kaggle notebook and import `kaggle_notebook.ipynb` (*File → Import Notebook*).
2. *Settings → Accelerator → GPU T4 x2* (only `cuda:0` is used) and *Settings → Internet → On* (to download the checkpoint).
3. *Run All*. Expected runtime is roughly 10–30 minutes on a T4, depending on how often episodes run to the 50-step limit. The model is ~0.8 GB to download.
4. Outputs go to `/kaggle/working/siglip-vla-navigation/`: `results/*.csv|json`, `figures/*.png|pdf`, an updated `README.md`, and `siglip-vla-navigation-results.zip`.

The notebook is self-contained: it writes `src/`, `tests/`, `README.md` and `requirements.txt` with `%%writefile`, runs the unit tests, then the evaluation. Outside Kaggle:

```bash
pip install -r requirements.txt
python -m pytest -q tests                      # environment, proposals, planner, baselines (no model needed)
python src/evaluate.py --out .                 # full evaluation (needs a GPU for meaningful latency)
python src/evaluate.py --out . --fill-readme   # render the Results section
```

Useful flags: `--n-episodes 500`, `--max-steps 50`, `--crop-margin 0.25`, `--dtype float32`, `--reps 100`.
